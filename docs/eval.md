# 抽取质量评估（S2）

本文件记录 `scripts/eval-extract.ts` 的评估范围、已跑过的结果和已知缺口。结论先行：
**真实模型召回尚未测量**，当前只有指标链路与标注集自检的结果。不要把下面的
`--dry` 数字当成模型质量。

## 标注集现状

- 文件：`tests/fixtures/extract/labeled.json`
- 规模：**12 页 / 23 条期望引用**（11 页各 2 条，`p07-overseas-warehouse` 1 条）
- 标签来源：人工阅读页面正文后，挑出可以支撑「问题 / 求购 / 付费 / 转换 / 复购」判定的原句，
  逐字抄录为 `expectedQuotes`。`checkLabels` 会拒绝任何不在正文里的标签、过短/过长或重复的标签。
- 覆盖：跨境库存同步工具的官网问答、平台新闻、ERP 选型与实测、论坛贴、仓库/超卖原因分析。

### 为什么是 12 页而不是 30 页

构建计划 T4.4 的目标是 30 页。当前只完成 12 页，原因是标注只能人工做：

1. **标签不能来自模型输出**。用模型自己挑的句子当标准答案，测出来的是「模型是否复述自己」，
   不是召回率。每条标签都必须由人从正文里指出，并接受 `checkLabels` 的逐字校验。
2. **页面要先满足可引证条件**：正文可得、有明确的观点句、不是纯导航/列表页。搜索阶段抓到的
   页面里，相当一部分是登录墙、验证码或与主题无关的页面，不能进入标注集。
3. 12 页已经覆盖了本轮想验证的几类文本（产品文档、新闻、测评、论坛、原因分析），继续堆同样的
   模板只会增加条数、不会增加信息量；下一批应按下面的扩充计划补不同平台和不同信号。

**已知局限**：23 条样本的置信区间很宽，recall 差 1–2 条就会让数字跳变；当前结果只能用于发现
「明显回归」，不足以对其他模型排名。

## `--dry` 的作用与局限

```bash
pnpm exec tsx scripts/eval-extract.ts --dry
```

- 作用：用标注集的 `expectedQuotes` 冒充模型输出，走同一套 prompt、schema、`gateQuote` 与指标
  计算。它验证的是**匹配与统计逻辑**（NFKC/空白归一化、包含关系、去重、precision/recall 计算、
  退出码），并且不需要数据库和模型，可以放进 CI。
- 结果（2026-10-30）：12 页 / 23 条，recall 1.00，precision 1.00，gate 拒绝 0，退出码 0。
- **局限**：这是同义反复——输入就是标准答案，所以它**不代表模型召回**，也不能说明 prompt 好坏。
  它只能证明「标注集自检通过、指标函数没有算错」。

## 真实模式：未运行及原因

```bash
pnpm exec tsx scripts/eval-extract.ts
```

脚本读取真实的 `bulk` 链（与 S2 相同：同一 prompt、同一 schema、同一 gate），逐页调用模型，
按标注集计算 recall/precision。退出码：`0` 达标、`1` 低于 60% 门槛、`2` 无可用模型、`3` 标注集损坏。

2026-10-30 本机执行结果为 **退出码 2**：

```text
没有可用的模型：bulk 链为空。请在设置页配置 provider 与模型，或使用 --dry 只验证指标逻辑。
```

原因是本地数据库 `providers` / `llm_chains` 均为空（未配置任何模型提供方），
所以**没有任何真实模型召回数据**，本文件也不声称有。

复现真实评估：

1. `docker compose up -d` 启动 PostgreSQL，确认 `.env` 的 `DATABASE_URL` 指向它。
2. 在设置页（或直接写 `providers` / `llm_chains`）配置至少一个可用 provider，并把它放进
   `bulk` 链；模型必须支持结构化输出。
3. `pnpm exec tsx scripts/eval-extract.ts`，把输出的 Markdown 表与指标原样追加到下面的记录表。
4. 若所有页都调用失败，脚本以退出码 2 结束，不记为 0 分——「没测到」和「召回低」必须区分。

## 后续扩充计划

- 每次把标注集**扩大 10 页**后跑一次真实评估，并在上表追加一行；同一规模下换了模型或改了
  prompt 也各记一行。
- 门槛：**recall ≥ 60%**（`RECALL_FLOOR`）。低于门槛时先看被 gate 拒绝的条目与
  `source.failed` 的模型错误，再决定是改 prompt 还是换模型；不得通过放宽 gate 来提分。
- 同时观察 precision 与拒绝率；precision 高但 recall 低通常意味着 prompt 过于保守，
  拒绝率高则按构建计划的 20% 阈值告警处理。
- 新增页面时：优先补不同平台、不同信号类别；标签仍须人工逐字摘录，禁止用任何模型输出当标签；
  提交前 `pnpm exec tsx scripts/eval-extract.ts --dry` 必须退出 0（标注集自检 + 指标逻辑）。
